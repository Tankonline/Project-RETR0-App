# Staging control plane

Enabled only when `STORAGE_CONTROL_PLANE_ENABLED=true` and `STORAGE_ENVIRONMENT=staging`. Production remains disabled; no replication, account auth, public node directory, or Android selector is enabled.

Routes use `/v1/storage/nodes/{nodeId}/...` consistently. Lifecycle mutations (`approve`, `cancel`, `drain`, `undrain`, `revoke`) require the staging-only `X-Storage-Admin: staging` authorization marker and are audited. Enrollment is idempotent for the same node/public key, validates fingerprint/public-key encoding, bounded body and code, timestamp/TTL, state, and capacity. Replay insertion is atomic via `INSERT OR IGNORE`; expired nonce rows are scheduled for bounded cleanup. Rate limits return normalized JSON `429` responses with request IDs.

The heartbeat contract is `POST /v1/storage/nodes/{nodeId}/heartbeat` with a JSON envelope whose signed canonical bytes are the exact UTF-8 JSON object `{version,commandId,nodeId,type,issuedAt,expiresAt,nonce,payloadHash}` in that order. `payloadHash` is SHA-256 of canonical JSON `payload`; `signature` is excluded and is URL-safe unpadded base64 Ed25519 in the JSON envelope. Timestamps are RFC3339Nano strings, with ±5 minutes clock skew and a maximum 15-minute TTL. The Worker looks up the enrolled Ed25519 public key and verifies its stored SHA-256 fingerprint before atomically consuming the nonce. No secrets are logged. Altered path/body, expired timestamp, invalid signature, and replayed nonce are rejected. The format is documented in `protocol/README.md` and `protocol/cross-language-vector.json`. Existing migrations are immutable; `0013_staging_control_plane_reconcile.sql` reconciles empty or staging schemas without changing production history.
