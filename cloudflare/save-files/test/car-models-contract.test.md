# Car-model local test matrix

Deterministic fixture: 27 files, 16,264,441 bytes, target `2001_bmw_m3_gtr_street`, package `com.ea.games.r3_row`, ATC assets, and `nfs/silver` variants. Keep bytes and secrets out of the repository.

- Manifest/path validation: require manifestVersion/packageType and package metadata; require source and destinationRelativePath metadata with destination containment; accept canonical `path`/`size`/`root` plus Android compatibility aliases; `REPLACE` remains vehicle-only, while `ADDON` accepts `VEHICLES_DATA`, `DEPOT_DATA`, and recognized depot-root metadata (`gametext.txt`, `gametext/text_*.txt`, `gametext/asset_list_base.txtCache.txt`, `text_*.txt`, `asset_list_base.txtCache.txt`); reject unknown top-level files, absolute paths (including drive-letter paths), `..`, backslashes, empty segments, duplicate paths, destination collisions, invalid SHA-256/size, zero-byte files, unsupported package IDs, >256 files, files over 20 MiB, and totals over 520 MiB; exact limits pass and one byte over each limit fails; preserve ATC/ETC names and unknown extensions.
- Idempotent draft creation: same owner plus valid `Idempotency-Key` returns the original UUID; another owner does not receive it.
- Upload/publish gating: reject undeclared files, size/hash mismatch, missing required files, missing cover, and incomplete R2 verification; publish immediately after all integrity gates pass. No moderation or automatic moderation is performed.
- R2 containment: every key is derived as `car-models/{uuid}/...`; client-supplied keys are ignored; traversal cannot escape the model prefix.
- Visibility/list/detail: drafts and uploading models are owner-only; published models appear in list/detail/assets only when the manifest, cover, and every declared package file still exist in R2; missing manifest, cover, or declared files are excluded, return not-found, and atomically persist `invalidated_at`/`invalid_reason`. Invalidated, hidden, and deleted rows are excluded from catalog, details, files, cover, screenshots, likes, and reports. Owner access never downloads an invalid published package; only existing draft/uploading owner routes may expose state.
- Repair/refresh: list validation is bounded to a small overfetch of the requested page, excludes invalid rows synchronously, clears likes, action-closes reports, and schedules idempotent full `car-models/{id}/` prefix cleanup without deleting child metadata; repeated detection is harmless. Android successful refresh replaces the current gallery list and a 404 detail returns to the gallery.
- Contract invalidation cases: missing manifest, missing cover, missing declared file, repeated invalidation, route exclusion, and persisted invalid state are deterministic and must remain covered.
- Like/report/delete authorization: likes/reports require signed identity; reports accept only known reasons; signed `DELETE /v1/car-models/{id}` changes only the owner's non-deleted model to hidden, sets `deleted_at`, returns HTTP 202 with `deleted:true`, and schedules `car-models/{id}/` prefix cleanup; non-owner/missing/repeated deletes return `404 model_not_found`. Client retry after `unknown_installation` must re-register once and retry the same signed DELETE.
- Regression smoke: existing installation authentication, `/v1/skins`, `/v1/music`, `/v1/saves`, manifest, cover, screenshot, and avatar route helpers remain unchanged.

No executable Worker test runner was present in the local package, so this is a deterministic harness specification rather than a new dependency or production test claim.
